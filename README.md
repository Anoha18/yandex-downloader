# yandex-downloader

Выгрузка всех файлов с Яндекс.Диска на локальный носитель, включая безлимитное
фото-хранилище («Фото» с телефона): сканирование Диска, каталогизация медиа,
докачка после остановки и бережное отношение к лимитам Яндекса (429/503).

> Статус: **Этап 4 (готов)**. Реализованы: OAuth (`auth`), `whoami`, `ls`, скан
> Диска (`scan`, конкурентный), каталог безлимитных фото (`photos`) с
> автополучением cookies, `stats` и скачивание (`download`) — файлы с сохранением
> структуры и фото в `<downloadDir>/_unlimited_photos`.

## Требования

- Node.js **>= 22.5** (используется встроенный `node:sqlite`; проверено на Node 24).
- pnpm.
- Для безлимитных фото — браузер Playwright (устанавливается отдельно).

## Установка

```bash
pnpm install

# для работы с безлимитными фото (одноразово скачает Chromium ~150 МБ):
pnpm exec playwright install chromium
```

## Настройка OAuth

1. Откройте https://oauth.yandex.ru/ → **«Создать приложение»**.
   - Тип: **«Для доступа к API»**.
   - **Доступ к данным:** `cloud_api:disk.read` (при желании `cloud_api:disk.info`).
   - **Платформы → Веб-сервисы → Redirect URI:** `https://oauth.yandex.ru/verification_code`.
   - Сохраните и скопируйте **ClientID** и **секретный ключ** из свойств приложения.

2. Скопируйте `.env.example` в `.env` и заполните:
   ```
   YD_OAUTH_CLIENT_ID=...
   YD_OAUTH_CLIENT_SECRET=...
   ```

3. Авторизуйтесь (браузер откроется сам; `--no-browser` — если открывать некуда):
   ```bash
   pnpm dev auth
   ```
   Токен сохранится в `data/token.json` (права `0600`).

## Быстрый старт

```bash
pnpm dev whoami          # аккаунт и занятое место
pnpm dev ls /            # содержимое корня Диска

pnpm dev scan            # обход Диска → очередь в data/state.db
pnpm dev scan --concurrency 6   # ускорить (по умолчанию из профиля)

pnpm dev photos collect  # безлимитные фото → каталог в БД (cookies подтянутся через браузер)
pnpm dev stats           # сводка по очереди и фото
```

## Команды

| Команда            | Назначение                                          | Статус |
| ------------------ | --------------------------------------------------- | ------ |
| `auth`             | авторизация, сохранение токена                      | ✅     |
| `whoami`           | информация об аккаунте и диске                      | ✅     |
| `ls <path>`        | список содержимого папки                            | ✅     |
| `scan`             | обход диска, наполнение очереди                     | ✅     |
| `photos`           | безлимитные фото: `collect`\\|`auth`\\|`status`\\|`export` | ✅ |
| `stats`            | сводка по очереди и фото из БД                      | ✅     |
| `download`         | скачивание файлов и фото                            | ✅     |
| `cleanup`          | уборка частичных загрузок `.part`                   | ✅     |
| `config`           | `init` \\| `show` \\| `path` \\| `template`          | ✅     |

Глобальные флаги: `--config <path>`, `--profile <gentle|normal|fast>`,
`--verbose` (`-v`), `--no-browser`, `--help` (`-h`), `--version`.

Флаги `scan`: `--deep`, `--path <dir>`, `--export <file>`, `--concurrency <n>`.

Флаги `photos`: `--refresh` (заново получить cookies), `--cookies <file>`,
`--browser-profile <dir>`, `--browser <chrome|msedge>`.

Флаги `download`: `--files`, `--photos`, `--path <dir>`, `--concurrency <n>`,
`--limit <n>`, `--retry-failed`, `--recheck`, `--dry-run`, `--download-timeout <с>`
(таймаут ожидания ответа при скачивании, по умолчанию 30с), `--stall-timeout <с>`
(простой без данных для фото, по умолчанию 60с). `--quiet` — глобальный.
По умолчанию скачивает и файлы, и фото. md5 проверяется всегда.

Если хранилище не отвечает (edge жив, а backend не отдаёт объект — сбой на стороне
Яндекса), файл быстро помечается `failed` без долгих ретраев; позже доберите его
командой `yd download --retry-failed`.

Незавершённые загрузки лежат рядом как `<файл>.part` (для докачки по Range).
Убрать лишнее: `yd cleanup` (по умолчанию — только устаревшие/осиротевшие `.part`),
`yd cleanup --all-parts` — удалить все частичные загрузки, `--dry-run` — показать.

При `--concurrency 1` прогресс показывает текущий файл с процентами; при
`--concurrency > 1` — агрегатную строку (`активных N`) без мигания, а каждый файл
отдельной строкой (`↓`/`✓`/`↷`/`✗`). Повторы пишутся как `↻ повтор N/M …`.

### Прогресс и логи

Длительные команды (`scan`, `photos collect`, `download`) показывают живой прогресс:
строка старта, обновляемый прогресс (текущий файл/папка, объём, скорость, ETA),
итоговые счётчики, а при простое — `… ожидание данных (Nс)`. `auth` сообщает шаги
(`✓ Браузер открыт`, `✓ Токен получен`), `whoami`/`ls` — короткий стартовый маркер.

Прогресс дублируется в `data/logs/<команда>.log`. Глобальный флаг `--quiet`
оставляет только ошибки и итог.

## Безлимитные фото (photoslice)

Фото, загруженные в «безлимит», **не отдаются** через Disk REST API/OAuth — они
лежат в отдельном хранилище (`photoslice`) и доступны только через web-сессию.
Скрипт получает cookies автоматически через **Playwright**: открывает браузер с
персистентным профилем `data/browser-profile`, вы один раз логинитесь, cookies
сохраняются в `data/cookies.json` и используются дальше.

```bash
pnpm dev photos collect   # собрать каталог (при необходимости откроет браузер для логина)
pnpm dev photos status     # сводка по собранным фото
pnpm dev photos auth       # только получить/обновить cookies (--refresh)
pnpm dev photos export photos.json
```

Альтернатива: `--browser-profile <dir>` — подхватить cookies из вашего
установленного Chrome (браузер должен быть закрыт). `--browser chrome` — не
качать встроенный Chromium, использовать системный.

> Это неофициальный интерфейс и серая зона по ToS Яндекса. Используйте только для
> своих данных. Cookies живут часы–дни: срок проверяется автоматически, и при
> истечении (или при `401/403`) cookies **пересобираются через браузер** и запрос
> повторяется — перелогин обычно не требуется, т.к. сессия хранится в профиле.

Каталог собирается постранично через `mpfs/list` (папка `/photounlim`): сразу
известны имя, размер и md5 каждого файла. Скачивание — **по одному файлу** по
подписанной ссылке `mpfs/url`, с проверкой размера/md5 и статусом по каждому фото
(`pending` / `downloaded` / `skipped` / `failed`). Массовая выгрузка ZIP
(`mpfs/bulk-download-prepare`) отключена Яндексом, поэтому она не используется.

Сбои хранилища (`HTTP 5xx`, таймауты) не «сжигают» время: файл просто помечается
`failed`, а частые повторы одного файла через паузы не делаются. Частота запросов
ограничена отдельным лимитером (чтобы не упереться в `HTTP 429`). Упавшие фото
возвращаются в очередь флагом `--retry-failed`:

```bash
yd download --photos --retry-failed
```

## Конфигурация

Два слоя (вариант A):

- **`.env`** — только секреты/учётные данные: `YD_OAUTH_CLIENT_ID`,
  `YD_OAUTH_CLIENT_SECRET`. Загружается встроенным `process.loadEnvFile`.
- **`data/config.json`** — только поведение: `downloadDir`, `photosDir`, `profile`,
  `rateLimit` и пути. Создаётся командой `config init`.

Если `photosDir` не задан явно (ни в конфиге, ни в `YD_PHOTOS_DIR`), безлимитные
фото складываются в `<downloadDir>/_unlimited_photos`. Относительный `photosDir`
считается от корня проекта.

Всё локальное состояние — в каталоге `data/` (gitignored):

```
data/
├── config.json       # поведение
├── token.json        # OAuth-токен (0600)
├── cookies.json      # cookies web-сессии для photoslice (0600)
├── browser-profile/  # персистентный профиль браузера Playwright
├── state.db          # очередь файлов и каталог фото (SQLite, WAL)
└── logs/
```

Приоритет: **defaults → config.json → env (YD_\*) → CLI-флаги**.

Профили нагрузки (`profile`) задают QPS метаданных и число одновременных запросов:

| Профиль  | QPS | concurrency |
| -------- | --- | ----------- |
| `gentle` | 2   | 1           |
| `normal` | 4   | 3           |
| `fast`   | 8   | 6           |
